# .gitignore Guide for FOS-Streaming v70

## Overview

The `.gitignore` file has been updated to follow Laravel and modern PHP development best practices. This ensures that only source code and configuration templates are committed to version control, while excluding generated files, dependencies, and sensitive data.

## What's Excluded

### 1. Application Cache & Temporary Files
```
/cache/*                # Application cache directory
/hl/*                   # HLS output directory
*.log                   # All log files
```
**Why:** These are generated at runtime and should be recreated on each deployment.

### 2. IDE & Editor Files
```
.idea                   # PhpStorm/IntelliJ IDEA
.vscode                 # Visual Studio Code
*.swp, *.swo            # Vim swap files
.DS_Store               # macOS Finder
*.sublime-*             # Sublime Text
```
**Why:** These are personal development environment files that vary between developers.

### 3. Environment & Configuration
```
.env                    # Main environment file
.env.local              # Local overrides
.env.*.local            # Environment-specific locals
.env.backup             # Backup files
.env.production         # Production config
```
**Why:** Contains sensitive credentials (database passwords, API keys, etc.). Only `.env.example` should be committed.

### 4. Composer Dependencies
```
/vendor/                # All Composer packages
composer.lock           # Lock file (can be excluded for libraries)
composer.phar           # Composer binary
```
**Why:** Dependencies are installed via `composer install`. The lock file can optionally be committed for applications to ensure consistent versions.

**Note:** For this project, `composer.lock` is actually tracked to ensure everyone uses the same package versions. You may want to remove it from `.gitignore` if you prefer this approach.

### 5. Node.js & NPM
```
node_modules/           # NPM/Yarn packages
npm-debug.log           # NPM debug logs
yarn-error.log          # Yarn error logs
package-lock.json       # NPM lock file
yarn.lock               # Yarn lock file
```
**Why:** Node modules are installed via `npm install` or `yarn install`.

### 6. Laravel/PHP Framework Files
```
/bootstrap/cache/*              # Compiled framework files
/storage/framework/cache/*      # Framework cache
/storage/framework/sessions/*   # Session files
/storage/framework/views/*      # Compiled Blade templates
/storage/logs/*                 # Application logs
/.phpunit.result.cache          # PHPUnit cache
```
**Why:** These are generated by Laravel at runtime.

### 7. Laravel Sail / Docker
```
docker-compose.override.yml     # Local Docker overrides
/.docker/                       # Docker build artifacts
```
**Why:** Local Docker customizations shouldn't be shared.

### 8. Build Artifacts
```
/public/hot                 # Vite/Mix dev server
/public/storage             # Symlinked storage
/public/build               # Production builds
/public/css/                # Compiled CSS
/public/js/                 # Compiled JavaScript
mix-manifest.json           # Laravel Mix manifest
```
**Why:** These are generated during the build process.

### 9. Testing Files
```
/coverage/              # Code coverage reports
.phpunit.cache          # PHPUnit cache
_ide_helper.php         # IDE helper files
```
**Why:** Generated by testing and development tools.

### 10. Log Files
```
*.log                   # All log files
/logs/*.log             # Application logs
/logs/nginx/*.log       # Nginx logs
/logs/php/*.log         # PHP-FPM logs
npm-debug.log*          # NPM debug logs
```
**Why:** Logs are generated at runtime and can be huge.

### 11. Session Files
```
/sessions/*                         # Session directory
/storage/framework/sessions/*       # Laravel sessions
```
**Why:** Sessions are user-specific and temporary.

### 12. Backup Files
```
*.bak                   # Backup files
*.backup                # Backup files
*.old                   # Old versions
*.tmp                   # Temporary files
```
**Why:** Editor and tool-generated backup files.

### 13. Database Files
```
*.sql                   # SQL dumps
*.sqlite                # SQLite databases
*.sqlite3               # SQLite databases
*.db                    # Database files
```
**Why:** Database dumps can be large and may contain sensitive data. Use proper backup systems instead.

### 14. OS Generated Files
```
.DS_Store               # macOS Finder
Thumbs.db               # Windows thumbnails
desktop.ini             # Windows desktop config
```
**Why:** Operating system metadata files.

### 15. Security & Credentials
```
/credentials/           # Credentials directory
*.pem                   # SSL certificates
*.key                   # Private keys
*.crt                   # Certificates
*.p12                   # PKCS#12 files
id_rsa*                 # SSH keys
*.ppk                   # PuTTY keys
```
**Why:** **CRITICAL** - These contain sensitive security credentials and must NEVER be committed.

### 16. Compiled Files
```
*.compiled              # Compiled files
*.min.js.map            # JavaScript source maps
*.min.css.map           # CSS source maps
```
**Why:** Generated during minification and compilation.

### 17. Streaming Files (HLS segments, temp transcodes)
```
/www/hl/*               # HLS output directory
/www1/hl/*              # Alternative HLS directory
*.ts                    # MPEG-TS segments
*.m3u8                  # HLS playlists
!/www/hl/.gitkeep       # Keep the directory structure
!/www1/hl/.gitkeep      # Keep the directory structure
```
**Why:** These are generated by FFmpeg during streaming and can be large.

### 18. FFmpeg Temporary Files
```
/tmp/*                  # Temporary directory
/temp/*                 # Temporary directory
*.ffmpeg.log            # FFmpeg logs
```
**Why:** Temporary transcoding files and logs.

## Best Practices

### 1. Never Commit Sensitive Data
```bash
# ❌ BAD - Don't commit these
.env
credentials.json
*.pem
*.key
database.sql

# ✅ GOOD - Commit templates instead
.env.example
credentials.example.json
```

### 2. Keep Dependencies Out
```bash
# ❌ BAD - Don't commit dependencies
vendor/
node_modules/

# ✅ GOOD - Commit dependency definitions
composer.json
package.json
```

### 3. Exclude Generated Files
```bash
# ❌ BAD - Don't commit generated files
/cache/*
/storage/logs/*
*.log
public/build/

# ✅ GOOD - Let the build process generate them
```

### 4. Check Before Committing
```bash
# Review what will be committed
git status

# Check for sensitive files
git diff

# See what's being ignored
git status --ignored
```

### 5. Clean Up Accidentally Committed Files
```bash
# Remove from git but keep locally
git rm --cached .env
git rm --cached -r vendor/

# Commit the removal
git commit -m "Remove sensitive/generated files"
```

## Special Cases

### Composer Lock File

The `composer.lock` file is currently listed in `.gitignore`, but **you may want to track it** for the following reasons:

**Arguments FOR tracking `composer.lock`:**
- ✅ Ensures all developers use exact same package versions
- ✅ Prevents "works on my machine" issues
- ✅ Makes deployments more predictable

**Arguments AGAINST tracking `composer.lock`:**
- ❌ Can cause merge conflicts
- ❌ May need frequent updates

**Recommendation for FOS-Streaming:**
```bash
# Remove composer.lock from .gitignore
# Edit .gitignore and remove the line: composer.lock

# Then commit it
git add composer.lock
git commit -m "Track composer.lock for consistent dependencies"
```

### Database Files

SQL files are ignored by default. If you need to commit schema files:

```bash
# Create a dedicated directory for schema
mkdir -p database/schema

# Add exception to .gitignore
echo "!/database/schema/*.sql" >> .gitignore

# Commit schema files
git add database/schema/
```

### Log Files (for debugging)

If you need to commit a specific log for debugging:
```bash
# Force add a specific log file
git add -f logs/specific-error.log
```

## Verification

### Check What's Ignored
```bash
# See all ignored files
git status --ignored

# Check if a specific file is ignored
git check-ignore -v filename.ext

# List all tracked files
git ls-files
```

### Find Accidentally Committed Secrets
```bash
# Search for .env in history
git log --all --full-history -- .env

# Search for patterns in commits
git log -p | grep -i "password"
```

## Migration for Existing Repositories

If you're applying this `.gitignore` to an existing repository with committed files:

```bash
# 1. Remove all files from git index (keeps local files)
git rm -r --cached .

# 2. Re-add everything (respecting new .gitignore)
git add .

# 3. Review what's staged
git status

# 4. Commit the cleanup
git commit -m "Update .gitignore and clean up tracked files"

# 5. Push changes
git push origin master
```

**Warning:** This will show every file as modified in one commit. Consider doing this at a good milestone.
